# Kindle 日历插件需求文档

版本：V1.0 需求基线

整理日期：2026-11-26

项目：Kindle Paperwhite 3 日历与天气插件

本文件汇总用户已确认的产品需求，作为后续开发与真机验收的依据。具体布局参见 [DESIGN.md](DESIGN.md)，天气候选及检索依据参见 [WEATHER-RESEARCH.md](WEATHER-RESEARCH.md)。技术候选和已有原型不等于最终实现，也不等于通过真机验收。

## 1. 项目目标

将已越狱的 Kindle Paperwhite 3 用作可交互的日历、天气和待办终端。用户可以查看当前时间、天气、农历及宜忌，切换月历，按日期管理待办，并在没有网络时继续使用本地功能与已有天气缓存。

最终运行方案必须免费，能够在用户中国大陆网络环境下正常使用；不能把付费天气套餐或付费服务器作为必需条件。

## 2. 设备与使用环境

| 项目 | 已确认条件 |
| --- | --- |
| 目标设备 | Kindle Paperwhite 3 |
| 屏幕 | 1072 × 1448，黑白墨水屏，触控操作 |
| 固件 | 5.16.2.1.1 |
| 现有基础 | 已完成越狱，已安装 KUAL |
| 部署电脑 | Windows |
| 设备连接 | 普通 USB 存储模式；用户曾确认盘符为 E:，每次写入前重新核实 |
| 时间口径 | 中国标准时间，Asia/Shanghai |

不把 Node、现代浏览器、Python、USBNet 或 SSH 视为设备已具备的条件。正式运行时及所需依赖必须检查后确定。

## 3. 初版范围与交付物

### 3.1 必须交付

1. 可由 KUAL 启动的正式日历插件及安装、使用、卸载说明。
2. 日历页与月历页，两页使用同一套待办、位置和天气数据。
3. 免费天气接入、离线缓存及按两小时规则触发的更新功能。
4. 离线农历、节气和宜忌计算所需的本地组件；页面展示农历与宜忌，节气能力用于历法支持，不新增独立节气页面。
5. Kindle 真机测试记录，证明目标固件、触控、天气网络、离线恢复和退出行为符合要求。
6. GitHub 中保存需求、设计、源代码、打包方法、依赖说明和验证记录。

### 3.2 当前不纳入初版

账户登录、跨设备同步、云端待办、定时提醒、重复事项、天气预警通知、多个城市同时展示、额外主题或独立设置页。若以后需要，应另行补充需求。

## 4. 页面与操作要求

### 4.1 公共区域

| 编号 | 需求 |
| --- | --- |
| NAV-01 | 顶部保留当前城市，点击城市可修改天气位置。 |
| NAV-02 | 顶部展示剩余电量，并能够辨识联网/离线状态。电量读取设备真实值。 |
| NAV-03 | 顶部提供退出入口，退出后返回 Kindle 首页。 |
| NAV-04 | 底部仅保留“日历”“月历”两个入口，不保留“设置”入口。 |
| NAV-05 | 页面切换不触发待办丢失、日期串用或不必要的天气请求。 |

城市输入与待办编辑可通过覆盖面板实现，不作为新增的底部导航页面。

### 4.2 日历页

| 编号 | 内容及行为 |
| --- | --- |
| DAY-01 | 展示设备当前月日、星期、时和分；不要求显示秒。 |
| DAY-02 | 显示当天农历日期及宜忌摘要。宜忌来自选定的万年历组件，不能使用固定示例或随机文案作为正式数据。 |
| DAY-03 | 显示天气图标，能够区分晴、阴、多云、雾、雪等天气类型；未知天气使用明确的缺省状态。 |
| DAY-04 | 展示当前气温和当天最低/最高气温，温度单位统一为摄氏度。 |
| DAY-05 | 保留未来 24 小时气温摘要；可抽样呈现，但本地保存真实的完整逐小时数据。 |
| DAY-06 | 展示今天的待办及完成情况，并提供新增、修改、删除和勾选操作。 |
| DAY-07 | 日历页始终表示“今天”；从其他日期的月历切回时，不能继续显示其他日期的待办。 |
| DAY-08 | 跨午夜后切换到新日期，星期、农历、宜忌及今日待办同步更新；天气按新日期查找可用缓存。 |

上半部沿用已调整的布局：日期、星期和农历组成日期行；大号时间靠左，宜忌在右侧成组对齐；天气图标与当前气温组合，温度区间放在右侧。信息层级、字号和留白应适合墨水屏阅读。

### 4.3 月历页

| 编号 | 内容及行为 |
| --- | --- |
| MONTH-01 | 展示当前浏览月份的年月、每周星期和完整日期网格，周一为一周起点。 |
| MONTH-02 | 每个公历日期下显示对应农历；初一可显示农历月份，并正确区分闰月。 |
| MONTH-03 | 支持上一月、下一月；点击年月可回到本月。跨年月份计算正确。 |
| MONTH-04 | 今日、当前选中日期、有待办日期采用可区分的黑白标记。 |
| MONTH-05 | 点击任意日期后，下方展示该日期的待办，并支持新增、修改、删除及完成状态切换。 |
| MONTH-06 | 未安排事项的日期展示空状态和新增入口。 |
| MONTH-07 | 月历和农历不依赖联网。可浏览范围受离线历法组件约束时，应明确提示边界。 |

## 5. 待办管理

| 编号 | 需求 |
| --- | --- |
| TODO-01 | 每条待办关联一个公历日期，包含可唯一识别的标识、文字内容和完成状态。 |
| TODO-02 | 日历页新增事项归属于今天；月历页新增事项归属于当前选中日期。编辑面板显示所属日期。 |
| TODO-03 | 新增或修改时支持中文输入；内容为空或仅为空格时不能保存；取消编辑不改变原数据。 |
| TODO-04 | 修改文字不改变所属日期和完成状态。初版不要求移动事项到另一日期。 |
| TODO-05 | 每条待办前有方框，点击勾选，再次点击取消；保存后的状态与完成数量保持一致。 |
| TODO-06 | 每条事项提供明确的修改和删除按钮；删除后刷新列表、完成数量及日期标记。 |
| TODO-07 | 两个页面共享同一份本地待办数据，对同一日期的操作在切换后保持一致。 |
| TODO-08 | 待办增删改和完成状态在离线时可用；正常退出、重新启动后保留。 |
| TODO-09 | 多条事项采用分页等适合设备的方式展示，长文字换行；新增、修改、删除和完成操作不得被截断或遮挡。 |

删除确认、撤销方式、字数上限和单页条数尚未被用户指定，可在实现时确定；不能将演示原型的取值当作用户已确认限制。

## 6. 城市位置设置

| 编号 | 需求 |
| --- | --- |
| LOC-01 | 点击顶部城市进入位置输入，支持中文城市或区县名称。 |
| LOC-02 | 联网搜索匹配地点；重名地点提供行政区信息供选择，不直接猜测目标。 |
| LOC-03 | 保存匹配后的名称及数据源对应的城市 ID/坐标，后续查询直接复用。 |
| LOC-04 | 切换城市后读取该城市自己的缓存；联网且没有该城市缓存时立即请求天气。 |
| LOC-05 | 离线无法匹配新地点时明确提示，不把旧城市天气标记成新城市天气；原有配置和缓存不被破坏。 |
| LOC-06 | 位置选择持久保存，应用重启后仍有效。无需自动获取精确定位。 |

## 7. 天气数据与免费要求

| 编号 | 需求 |
| --- | --- |
| WEATHER-01 | 获取当前天气现象、天气代码/图标映射及当前温度。 |
| WEATHER-02 | 获取并保存 15 天逐日预报，包含日期、天气现象和最低/最高温度。验收口径沿用现有设计：今天及之后 14 天。 |
| WEATHER-03 | 获取并保存接下来 24 个连续的真实逐小时时段及气温，正确处理跨日。未来起点应接近当前时刻，不使用已过期的记录冒充未来预报。 |
| WEATHER-04 | 最终路线不要求付费天气订阅、到期试用或付费服务器；免费额度应覆盖本项目正常请求频率。 |
| WEATHER-05 | 必须在用户中国大陆网络及目标 Kindle 上实测。GitHub 项目说明、云端访问和模拟测试不能替代此项。 |
| WEATHER-06 | 验证响应内容、地区、字段、日期和发布时间；HTTP 200、响应非空或接口名称不是成功依据。 |
| WEATHER-07 | 缺失数据明确显示暂无数据；不得插值、随机生成或复用其他城市数据来伪装需求已满足。 |
| WEATHER-08 | 正式发布前确认数据服务使用条件、来源标注及所用组件许可证；免密钥不等于获得数据使用授权。 |

若候选数据源不能提供完整 15 天或连续 24 小时，记录为未满足需求；不得默默缩减为 3 天、7 天或逐三小时。若之后要调整范围，应取得用户明确的需求变更。

## 8. 离线与更新规则

### 8.1 请求决策

以下规则对实况、逐日和逐小时数据分别判断；以当前选中城市为范围。

| 设备状态 | 缓存状态 | 行为 |
| --- | --- | --- |
| 离线 | 有缓存 | 读取缓存，显示缓存时间；日历、农历及待办继续工作。 |
| 离线 | 无缓存 | 对应天气显示暂无缓存，不阻塞其他功能。 |
| 联网 | 无缓存 | 立即尝试获取。 |
| 联网 | 距最近成功获取小于或等于 7200 秒 | 继续使用缓存，不因页面切换或分钟刷新重复请求。 |
| 联网 | 距最近成功获取超过 7200 秒 | 尝试更新；等待期间先显示旧缓存。 |
| 更新成功且数据有效 | 任意 | 保存新数据及本次成功获取时间，更新页面。 |
| 更新失败或数据无效 | 有旧缓存 | 保留旧数据及旧成功时间，显示更新失败/缓存状态。 |
| 更新失败或数据无效 | 无旧缓存 | 显示暂无数据及失败状态，其他功能可用。 |

### 8.2 缓存质量与恢复

- CACHE-01：缓存按城市和数据类别隔离，不跨城市混用。
- CACHE-02：区分本机成功获取时间与上游发布时间；新下载的旧数据不能被标为实时数据。
- CACHE-03：保存前校验完整性，采用不会因写入中断而破坏旧数据的方式更新。
- CACHE-04：某个接口失败不清除其他类别的有效缓存，也不推进失败项的成功时间。
- CACHE-05：当天没有对应预报、小时记录已过期或无法覆盖未来时段时显示缺失，不把历史记录自动搬到今天。
- CACHE-06：离线实况温度标为“缓存气温”并带时间，避免被理解为当前观测值。
- CACHE-07：请求在后台执行，有超时及有限重试/退避；不能让天气失败卡住触控或在每次刷新时持续请求。
- CACHE-08：用户重新启动应用后，可以恢复配置、待办和已有天气缓存。
- CACHE-09：设备时间明显异常时提示时间问题，不声称已通过数据时效验收，也不强制修改系统时钟。

## 9. 农历、黄历与时间

- LUNAR-01：公历与农历对应正确，处理农历月份、初一和闰月，日历与月历结果一致。
- LUNAR-02：宜忌由本地万年历组件提供；摘要可以选取少量实际条目，但不能杜撰或把排版示例当作结果。
- LUNAR-03：所需组件与数据随插件安装，不依赖 CDN、在线黄历服务或第一次联网初始化才能显示农历。
- TIME-01：时分、日期、星期和“今天”按设备实际时钟及统一时区计算，不固定为演示日期。
- TIME-02：时间按分钟更新，分钟刷新不等于每分钟请求天气。跨午夜、跨月和跨年保持一致。

## 10. 设备交互与非功能要求

- 黑白高对比，天气类型、今日、选中和完成状态不依赖颜色区分。
- 关键文字、日期和操作按钮在目标屏幕上可读、可触控，无重叠、截断或不必要的全屏滚动。
- 时间刷新、局部内容更新和天气联网更新分离；优先局部刷新，控制残影与闪屏，不承诺尚未测量的耗电或响应指标。
- 应用必须可从 KUAL 启动，可在正常离线条件下进入页面，不依赖先打开外部网站。
- 退出应停止本应用自己的任务、妥善保存数据，并返回 Kindle 首页；不得用重启系统代替。
- 安装文件和用户数据应有清晰目录；提供卸载说明，不能误删 KUAL、其他扩展、书籍或系统文件。
- 测试和运行失败不得自动刷机、升级/降级固件、重做越狱、启用 SSH、安装未知依赖或关闭证书校验。
- 诊断日志与用户待办、位置配置不得默认提交到公共 GitHub；仓库只保存必要代码、文档及可公开测试数据。

## 11. 数据持久化要求

以下是必须覆盖的信息，不强制具体语言、文件格式或数据库方案。

| 数据类别 | 需要保存的信息 |
| --- | --- |
| 位置配置 | 地点显示名称、行政区、来源及其城市 ID/坐标、时区。 |
| 待办 | 唯一标识、所属公历日期、文字内容、是否完成。 |
| 天气缓存 | 城市标识、来源、数据类别、单位、成功获取时间、上游发布时间、带日期/时间的天气记录。 |
| 诊断结果 | 设备与工具兼容性、请求结果、失败原因、实际预报时间覆盖；按需保留原始响应供分析。 |

每次用户确认保存的待办和位置应能在正常重启后恢复；不能只依赖页面内存。天气缓存与待办分开管理，更新天气失败不得影响待办。
